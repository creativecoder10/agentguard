AgentGuard: a security gate for AI coding agents

Telling an AI agent "you're read-only" in a prompt doesn't make it read-only — a poisoned file can talk it out of that. AgentGuard sits between the agent and its tools and enforces policy in code the agent can't argue with. Below: three attacks and one normal task, run through the real proxy, with every decision taken straight from its audit log.

Results

The agent in these runs is scripted to obey every injected instruction — the worst case. The question is whether anything harmful still gets through.

How it works

AgentGuard is an MCP proxy, so it protects any compatible agent (Claude Code, Cursor, or a custom one) without changes on the agent side.

AI agent

Decides which tool to call. Can be wrong, or manipulated by text it reads.

→

AgentGuard

  1. Input gate — tool allowlist, sandbox containment (checked twice), destructive actions denied, task-scoped writes.
  2. Output scan — secrets redacted and injection text fenced off before the agent sees a tool's result.
  3. Session taint — once the agent reads untrusted data, it loses the right to change anything without a human.

What this does — and doesn't — prove

Stated up front, because a security claim without its limits isn't worth much.

The boundary is the gate, not detection

Injection detection is pattern matching, and one scenario is deliberately written to slip past it. It's a tripwire and an audit signal; what actually stops the attack is policy that holds whatever the agent believes.

Scripted agent, real everything else

The agent's choices are scripted so runs are repeatable and show the worst case. The proxy, the MCP protocol, the policy checks and the files on disk are all real. A live mode runs the same attack against Claude.

Safety costs some convenience

After reading untrusted data, even a legitimate write is blocked until a human approves — the approval prompt is the next phase. Failing closed is the deliberate trade.

Known gap

A payload that evades the scanner, in a file not labelled untrusted, won't taint the session. Task-scoped writes limit what that session can touch. It's written up in the threat model.
